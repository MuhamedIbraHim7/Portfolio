Retail Analytics Copilot.

Answers retail questions using policy documents and Northwind sales data. A LangGraph workflow selects retrieval, SQL or both.

Overview

“How long can a customer return a beverage?” needs a policy. “Which category sold the most during a campaign?” needs a date range and a calculation. I built a local copilot that can take either path.

The problem

Business definitions live in documents while sales figures live in tables. A query can execute successfully and still answer the wrong business question.

Who it serves

Analysts exploring how a local language model could combine policy lookups with sales calculations.

My contribution

I implemented the agent graph, added worked SQL examples for the local model and reconciled campaign dates with the sample database.

System design

The graph routes each question to document search, SQLite or a hybrid flow. For hybrid questions, retrieved definitions and dates guide SQL generation. Results include the answer and its source documents or tables.

Tools & components

  • DSPy
  • LangGraph
  • SQLite
  • Ollama
  • Python

Results & trade-offs

Five of six questions answered correctly in the documented evaluation.

Implementation decisions

A small local model kept inference on the machine but needed worked examples for SQLite joins and dates. The campaign calendar also had to agree with the years in Northwind.

Testing & reliability

In the six-question evaluation, an all-time ranking returned no rows because the planner added an irrelevant campaign date. The saved output exposes the SQL so the error can be traced.

Data handling

The prototype runs against the Northwind sample database. Connecting to business data would require read-only credentials, table-level access control and query limits.

Next steps

I would protect all-time questions against inherited date filters and test the planner on a larger held-out set with read-only database access.
