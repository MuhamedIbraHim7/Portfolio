Multilingual RAG Assistant.

Searches a collection of question-and-answer passages, reranks close matches and checks whether the retrieved text can support an answer.

Overview

A search system can look accurate when people repeat the wording in its index. I built this question-answering API and measured what happened when the same questions were asked in different words.

The problem

Similar passages compete for first place. Reranking every query adds latency and can reorder an already strong match.

Who it serves

Developers evaluating retrieval quality before adding a question-answering API to an application.

My contribution

I built the indexing pipeline, added confidence-gated reranking and exposed the retrieval and generation stages through FastAPI. I compared verbatim questions and paraphrases on the same sample.

System design

FAISS searches question-and-answer text embedded with a multilingual encoder. When the top scores are close, a cross-encoder reranks the candidates. The response can answer, surface a passage or decline.

Tools & components

Results & trade-offs

Retrieved the expected passage first for 80 of 100 paraphrased questions.

Implementation decisions

Reranking answer text alone pushed correct matches down the list. Matching the index representation and reserving reranking for close calls restored two documented regressions.

Testing & reliability

The evaluation uses the original passage ID as its target. On 100 paired questions, rank-one retrieval fell from 95 verbatim matches to 80 paraphrased matches. Near-duplicate passages can make this measure stricter than a reader's judgment.

Data handling

The API records requests by session. A shared deployment would need authentication, per-session access checks and a retention policy for questions and responses.

Next steps

I would add human judgments for equivalent passages and a separate multilingual query set to test the encoder beyond the existing English evaluation.
