Overview

A voice interface has to listen and respond while the person is still engaged. At Neqabty, I built and deployed a real-time system for spoken interactions.

The problem

The time spent transporting audio, processing speech and producing a response is felt as one pause by the speaker.

Who it serves

People using a spoken support interface and the engineers integrating it with the client application.

My contribution

I connected WebSocket streaming to the Azure OpenAI Realtime API and GPU-accelerated speech services on A100 infrastructure.

System design

The system carries audio over a persistent connection and brings together speech recognition, conversational inference and synthesis. The diagram groups the documented components by their purpose.

Tools & components

  • Azure OpenAI Realtime
  • WebSockets
  • GPU speech processing
  • Azure A100

Results & trade-offs

Deployed a working speech-to-speech system at Neqabty.

Implementation decisions

A persistent connection supports interactive audio. It also makes interrupted sessions and network delays part of the user experience.

Testing & reliability

The engineering question is whether the full conversation feels responsive. A representative test would include transport, turn detection and output audio as well as model processing.

Data handling

Support conversations can contain personal information. A shareable recording would require participant consent or a scripted conversation using synthetic details.

Next steps

I would publish an approval-cleared demo and a latency distribution with explicit measurement points and network conditions.
